# Graded abstention output: results

Date 2026-10-22. Card: `CARD.md`, amendment: `AMENDMENT_1.md`.

## What was added

One additive key, `abstain_reason.near_miss`, written only under the existing
`EYEKB_ABSTAIN_REASON` opt-in and only when the ranking came back empty. It lists up
to three candidates that were demoted **only** because they are state programs or
because they missed the increment-admission bar, with the guard's own
`n_shared` / `shared_genes` / `needs_n_shared` / `best_incumbent_n_shared` copied
through verbatim.

Nothing is scored or re-ranked. `celltype_ranking` stays empty on abstention, so the
answer is still `unknown` and no metric moves.

## Acceptance criteria

Corpus: the 25 volumes / 764 clusters of the independent validation wave, genes taken
from each cluster's evidence report, default composite route (`library="all"`).

| id | criterion | result |
|---|---|---|
| P1 | default route, switch OFF | **764/764** responses byte-identical; **764/764** ranking sequences identical; 0 errors |
| P2 | switch ON, near_miss empty | all six pre-existing `abstain_reason` fields identical on **764/764** |
| P3 | switch ON, near_miss written | pre-existing fields unchanged; key appears only where the ranking is empty |
| P4 | red line | **0** entries from `tissue_out_of_scope` or `composite_superset` |
| P5 | G4 reproduction hash | **unchanged** — see the note below |
| P6 | unit cases | **6/6** |

## Coverage

| | count |
|---|---|
| clusters with an empty ranking under the opt-in switch | 215 |
| of those, a `near_miss` list is written | **20** |
| of those, nothing came close (key absent, old bytes) | 195 |

The 20 are clusters where something was nearly answerable. The other 195 are the
honest empty case: no marker overlap, nothing demoted, nothing to report. That ratio
matches the independent analysis of the same corpus, which found 85.9% of abstentions
carry no affirmative claim at all.

Worked example (`CX04_cowan_periphery::19`):

```
celltype_ranking: []
near_miss: [{"cell_type": "Proliferating", "n_shared": 1,
             "shared_genes": ["STMN1"], "why": "state_program_only"}]
```

## P5 note — a pre-existing defect, not caused here

The G4 pipeline gate reports 2/3 files matching, with
`annotation_evidence_report.md__normalized` producing `7c225802…` against an expected
anchor of `6f795b32…`.

This was verified by reverting `mcp_server/eyekb_core.py` to HEAD
(sha256 `783e1720…`), re-running `tests/verify_pipeline.py`, and obtaining the same
`7c225802…`; restoring the change (sha256 `bf101cef…`) leaves it unchanged. The
expected anchor is stale. Re-anchoring changes the acceptance baseline and therefore
requires its own card — it is not folded into this one.

## Unit checks

The unit script does not trust synthetic responses. It re-runs the 20 clusters that
actually produced a list and cross-checks every entry against the same response's
`state_annotations` and `antseg_guard_demoted` records:

* U1 empty score carries no key
* U2 a ranked response carries no key
* U3 every entry traces to its own demotion record
* U4 no wrong-class demotion leaks (tissue / composite / out-of-scope)
* U5 capped at 3, sorted by `n_shared` descending
* U6 switch OFF never carries the key

## Reproduction

```
cd docs/plans/abstain_grade_20261022/scripts

```

The two full corpora files (`out/NEAR_MISS_CAPTURE.json`,
`out/NEAR_MISS_VERIFY.json`, ~630 KB each) are kept on the working disk and are
regenerated by the commands above; they are not committed, since the scripts rebuild
them exactly.
