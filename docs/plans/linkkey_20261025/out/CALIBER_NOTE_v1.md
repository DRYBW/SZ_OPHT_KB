**两条记录用的是同一个字段。** 源码级锚点（行号已核，可直接打开）：

四条互相独立的旁证（均由 `build_connect_key.py` 从盘上现算，见 `LINKKEY_STATS_v1.json`）：

⇒ **"对上率 100 %" 只适用于「标识键」这一个口径**，其成立依赖 `paper_id ≡ pmid` 这一**构造事实**

## 3. 为什么题名口径只有 30.26 % / 44.83 %（两处结构性缺陷）

同样是源码级归因，不是"估计写法差异"：

1. **引用侧题名被硬截到 120 字符** — `kb/link_registry/scripts/build_link_registry.py:211` → `"title": (hit.get("title") or "")[:120]`。
   实测：803 条被引记录里 **122 条题名长度正好 = 120**、**0 条 > 120**（截断确实在生效）。
   截断把单词切成两半（例：`…mediates`、`…and Y`、`…Retinal Organoid`），全等判定必然失败。
2. **442 / 803 条引用侧根本没有题名** — 同文件 `:278` → `"title": ""`。
   这批是经 **gene index（全文扫描）** 补进来的引用（`evidence_source="gene index (full text)"`），
   build 时就没写题名。**题名键对它们从定义上不可用**，与"写法差异"无关。
3. 附带一处真实起因：语料侧有 **41 行题名含 HTML 实体**（如 `&lt;i&gt;PRRX1&lt;/i&gt;`），
   规范化后与引用侧的纯文本题名不等（A 口径唯一的 1 条 `TITLE_REWRITTEN`，sim=0.9316 就是这个）。

**与协调者实测数的差异登记**：协调者报 186/803（23.2 %）严格、263/803（32.8 %）前缀；
本卡复算得 243/803（30.26 %）、360/803（44.83 %）。差异来自**规范化细则与"同一 pmid 多条引用取哪条题名"**
的选择（本卡取最长题名；截断侧长者信息量最大）。**登记为口径差异，非任一方错误**——
双方数字都在同一量级、同一成因。本卡的每个数都可由 §8 的命令从下述两个 sha 复算。
