## 回稿全文（原文照录，仅删流式头部空行）

我会重点核对共享基因屏蔽的标签依赖、部分重投与 RUN5 的可比性，以及净增 3 个命中的依据；也会区分实现上能保证的规则与仍需数据验证的效果。

设计中有两处需要先澄清：R3 的"其它 truth 类"尚未定义 Keratocytes 如何归类，因此"KERA 必被屏蔽"目前推不出来；R2/R3 只改变排名计分，也不能改变 KB7 的逐基因准入结果，不能据此把既有阴性转成可建词条。部分重投可以用于缓存式自检，但需要限制它与 RUN5 比较时的结论。

**审查结论：建议"修订后再冻结"。** 补建 Melanocyte/Schwann、限制组织适用性、保留既有阴性结果，这些方向可以成立；当前方案尚不能保证"阻断接管，同时保住真免疫证据"，也不足以预测能够达到 24/33。部分重投可以作为离线自检，但必须明确其统计解释边界。

以下判断仅针对设计，不把 RUN5 的既有归因当作已经证实的因果结论。

### 1. author_class_markers_data.tsv 虽然与 KB 无关，仍然依赖本次评价数据的真值标签

R2/R3 使用同一 D002 的作者分组来决定哪些基因能支持哪些类别，再在 D002 的 33 簇上评价。这属于利用评价集标签进行规则开发。文件提前冻结可以防止后续挑选修改，却不能消除这种依赖。

因此，KB9 可以定位为"基于 RUN5 已知错误的开发集定向修复与回归检查"。24/33 若达标，是该开发集上的工程验收结果，不能作为独立验证的性能增益。已有错误定位、作者组 marker 和既有 KB7 结果均已知，也应在预注册中明确这一点。

"判分/裁定侧禁食同源证据"需要给出操作定义：作者标签生成屏蔽表，屏蔽表改变 ranking，ranking 再进入判读席，仍存在间接的信息传递。仅声明判读席没有直接看到 truth，不能证明证据链独立。若该纪律要求整个判读输入不依赖评价标签，现有 R2/R3 不满足；若允许建设侧使用这些标签，就应明确将本轮定位为开发集自检。新词条所用 agg 参考池也应登记与 D002 的 study/donor 重叠情况。

更干净的验证路线是：在独立眼表参考数据上确定屏蔽或谱系支持规则，然后冻结后评价未参与开发的 study/donor。仅在当前 D002 内重新切分，不能消除已经查看全部 RUN5 错误带来的开发依赖。

### 2. R1 可以保证指定条目不进入排名；R2/R3 不能单凭规则保证接管消失，也不能保证真免疫证据保留

按现有描述，屏蔽后的分数相当于：

n′(簇 c，类别 t) = 前10基因中，属于 t 的 marker、且未被屏蔽的基因数。

这个规则会在所有眼表簇中删除相应支持，包括 Q6::8/26。CD74/HLA 或 S100A8/9 出现在非免疫作者组 top60，可以提示跨谱系表达、状态效应、环境 RNA 或组内混合，却不能单独证明其在真实免疫细胞中没有判别价值。"任一其他类 top60"还是一个较强的删除条件；反过来，不进入其他类 top60 也不证明特异。

即使删掉目标共享基因，错误免疫条目仍可能靠其他命中留在 top3；即使错误条目退出，正确条目也未必补位。这里必须补上一条明确规则：**n_shared=0 的类别不得进入 top3；不足三个有效候选时保留不足三个，不能靠加载顺序补齐。新增词条的加载位置和平票规则也要冻结**，否则新条可能持续输给旧条。

投票前应固定输出一张诊断表：各簇各候选的原始命中、删除命中、剩余命中、名次变化，以及 Q6::8/26 的免疫候选是否仍有有效支持、是否进入 top3。这能识别"证据被掏空"，但不能替代最终投票。如果要声称"不损伤 Q6::8/26"，还应将其正确共识保持作为单独的验收条件，不能只看总体 P1。

R1 按来源文件整批排除也过粗。来自视网膜文件的通用免疫或血管类别，不必然只适用于视网膜。建议将规则冻结为"条目 ID—组织适用范围"表，逐项说明排除依据，并处理同一类别在其他文件中的重复条目。来源文件可以作为实现索引，不能单独充当生物学排除依据。

### 3. R3 的"其它 truth 类"目前存在定义缺口，并与 KERA 的预期处置冲突

必须先冻结每个候选类别到九类评价词表的映射，再定义"其它"。

如果 Keratocytes 在该评价体系中属于 Fibroblasts，那么 Fibroblasts 就不是它的"其它 truth 类"。仅凭 KERA 出现在 Fibroblasts top60，不能推出 KERA 应被屏蔽，更不能推出 Keratocytes 的全部面贡献归零。若 Keratocytes 尚未确定映射，"其它 truth 类"对它就没有明确定义。不能因为名称与九类标签均不相等，就把所有九类都当作负类。

同样，九大类聚合 marker 不能充分解决 Fibroblasts 内部的角膜、巩膜细分，也不能识别所有上皮分层关系。评价词表中的合并关系和生物学亚型关系需要分开记录。

更干净的替代可以保持现有基因集不变，通过旁挂表区分"支持谱系身份的 marker"和"共享或状态性 marker"，并要求候选有预先定义的谱系支持才能入围。已被独立证据证明跨谱系表达的基因可以保留在上下文中，但不应单独授权某个谱系定名。该旁挂表应来自外部证据，不能继续用 Q6 truth 反向生成后再宣称独立。

这是一种替代设计，不是与当前屏蔽法效果相同的规则。没有一种仅凭 top60 共现就能保证同时消除假阳性和保留全部真阳性的等价规则；任何谱系门控也都需要检查在前10基因输入下的灵敏度。

### 4. 混合票集可以用于缓存式自检，但不等同于一次新的全量复测，也不足以隔离 KB9 的增益

如果实际系统的行为就是"证据不变则沿用存档票"，混合票集可以作为这个系统的一次验收输出。问题在于，将"改变输入后的新票"与"旧时点的存档票"比较，会混入采样随机性、服务端模型变化及批次上下文差异。温度 0.2 和参数相同并不保证结果可重复；这主要不是温度值漂移，而是推理结果及后端环境不完全固定。

"输入不变"还必须按模型实际接收到的完整请求判断，不能只比较 ranking/lit 两个字段。若"5/批"是五个簇共用一个提示或上下文，重新组批会改变未修改簇的输入环境；如果只是五个独立请求并发，则没有这项问题。预注册需要写清楚。

若希望较有说服力地比较性能，优先采用同一时段、相同完整输入条件下的 Arm1/Arm2 配对重投，隐藏臂标识并固定组批方式。资源受限时，至少应对所有变化簇同时重投 Arm1 和 Arm2，再单独报告未变化簇的缓存结果。后一方案仍不能称为完整的当期 33 簇复测。

另有三处必须修订：

- 保真门应同时覆盖 OFF 历史状态和与 RUN5 存档票对应的 ON 状态。仅复刻 OFF ranking，不能证明 Arm1 已复现 RUN5 的证据输入。
- top_genes 可以原样保留；gene_hits 若包含旧库候选、匹配基因或类别信息，就不能未经依赖检查直接搬运。否则被排名排除的条目仍可能通过其他字段进入判读。tissue_composition_ref 也应确认不含作者标签导出的答案信息。
- lit 重建是提案包的一部分，应冻结实际返回的文献、片段和顺序，并排除同源答案证据。当前设计能够评价"词条＋装配规则＋重建 lit"的组合效果，不能单独归因于词条补建。

新增 crosswalk 应在投票前冻结，已有名称的映射保持不变。若同时修改旧名称映射，RUN5 基线也需要按相同映射重新核算。

### 5. suprabasal 和纤维细分应优先继承 KB7 阴性；R2/R3 不能作为解除阴性的理由

同一数据、同一候选范围、同一统计实现、同一判据下，确定性的逐基因筛选应得到同一结果，不只是"大概率仍阴性"。直接登记"继承 KB7 的既有阴性裁定，本轮未产生新的阳性证据"，比重新寻找能过关的基因更合适。

当前 §1.1 的"换判据域，见 R2/R3 后新共享基因屏蔽域"**不成立**：R2/R3 改的是证据装配计分，并未改变 §1.2 的 CPM、LFC、CONS、donor 和火灾域要求。排名时忽略某些基因，不能让原先未通过准入的基因通过。

若所谓换域实际意味着删除不利的比较组或改变负类定义，那就是实质性的准入判据变更，需要作为新版本明确注册，不能沿用"KB7-W2 常量不变"的表述。

补充外部文献也不能自动抵消 data_driven 通道失败，因为 §2 要求三个通道均满足。可以登记外部文献支持的待验证候选；若要成为本轮核心词条，则须明确新的独立数据如何满足冻结的数据判据。

因此，"只补建 Melanocyte/Schwann，其余继承阴性"是合理的收缩方案，前提是这两个新条也逐项通过准入，不能因为它们属于覆盖缺口就降低标准。

### 6. 24/33 需要净增三个命中；当前残余表存在可能使目标不可达的算术问题

设原先错误、修复后正确的簇数为 G，原先正确、修复后错误的簇数为 L，则：

新 P1 命中数 = 21 + G − L；达标要求 G − L ≥ 3。

补两个词条不等于增加两个正确簇，去掉错误候选也不等于获得正确共识。与此同时，R1/R2/R3 可能使原先正确的簇失去支持，因此必须同时预注册"收益簇"和"回退簇"的报告方式。

预期代价表列了十个不同簇：24、15、28，以及七个弃权/tie 簇。若这十个都是 P1 miss，且全部预期保留，那么即使其余簇全对，上限也只有 23/33。若 Q6::24 只是 P2 违规而不构成 P1 miss，其余九个都保留为 P1 miss，则上限恰好是 24/33，要求其他所有簇正确且没有新增回退。必须逐簇分开填写 RUN5 的 P1 状态和 P2 状态，不能把两类残余混算。

仅从干预机制看，优先核查的翻转候选是：

- Melanocytes/Schwann 对应的原始错簇：新增词条提供了直接的支持路径，但仍取决于合格核心基因能否进入前10输入、进入 top3，并获得两席同名定名票。
- Q6::11 和 Q6::3：如果错误确由共享免疫基因驱动，且正确类别已有足够支持，屏蔽后有望改善；如果正确候选仍然缺失，更可能转成弃权。
- Q6::13：排除 MG/Astro 可以保证这些特定候选退出，但能否转为正确共识取决于替代证据。
- Q6::15/28：当前 R3 与 Keratocytes 映射尚未明确，不宜计入确定收益。
- Q6::24 和七个弃权/tie 位：不能仅凭当前描述排除改善可能，也不能预先将其全部锁定为不可修复。

没有逐簇的候选替代关系，无法可靠排序翻转概率。"至少净修复三个"可以作为目标，尚不能作为有依据的预测。

P2 同样没有余量：如果 Q6::24 的违规保留，其他簇合计必须零新增 strict 违规。"属于预期"不能成为超过 1/33 的豁免。

### 7. 残余归因、火灾审计和证据通道的表述还应收紧

"pericyte/SMC 生物学不可分"超出了当前设计能够支持的范围。较准确的表述是："在当前数据、特征选择、证据装配和判读协议下未能稳定区分。"共享 marker 或既有失败不能证明两种细胞在生物学上不可分。七个弃权/tie 位也应登记为待检验的失败机制假设；新增证据本来就可能改变弃权行为，投票后不能仅凭仍然 miss 就自动确认旧归因。

混合面审计中的"视网膜簇中新条零进入"，首先验证的是 applicability 的实现。由于规则本身禁止进入，这不能证明新条的 marker 具有独立的组织特异性。建议对这 22 个视网膜簇进一步要求 Arm2 与 Arm1 的完整 ranking 一致，以检查排序、去重或加载顺序等副作用；同时将该审计明确称为适用性规则与回归检查。

OLS 回证验证的是细胞术语及 CL 身份，通常不能验证某个基因是该细胞的 marker。因此它应属于词条级命名证据；逐基因支持主要来自文献中的实际表达/标志关系和数据统计，不能把 OLS、PMID、同源数据简单解释成三个独立支持来源。

最后，冻结前还需明确：每条词条最少需要多少个合格核心基因、少于要求时如何处置；§1.2"其余9互斥组"究竟对应哪套参考分组；以及所有低于 MINPOOL 而未参与否决的比较组。TOPN=12 只是上限，免于否决的比较组也不能被记作已通过特异性验证。
