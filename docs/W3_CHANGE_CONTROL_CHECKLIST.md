## 一、改前五问（缺一不许开工；答案必须带盘上证据）

### Q1 首因层是哪一层？（用证据定，不猜）
- 做法：跑 `UPSTREAM_FIRST_RULE.md` §1 Step 0-2，逐层取证。
- 交付：`首因层 = L?` + **该层证据的绝对路径 + 行号/列名**。
- 判据（机械）：证据串必须能被 `grep` 到；只写「应该是」「大概率」= **Q1 FAIL**。
- 今日正例：RGC 缺口的首因层=L2，证据 `C0_CANDIDATE_REACHABILITY.tsv`（RGC 0.2339）vs `REACH_DIFF_X9A_X9B.tsv` 第 17 列（0.8638）。

### Q2 拟修层 = 首因层？
- 是 ⇒ 继续。
- 否 ⇒ **不在该层修**。下游只可加**临时旗标**，且必须带：①到期日 ②上游修复指向（哪件/哪个卡）③删除条件。
- 判据（机械）：`拟修层 != 首因层` 且无「过渡件登记三要素」= **Q2 FAIL**。

### Q3 影响面？（上游变更的传染核算）
- 交付：**逐臂 × 逐读数** 的被动态清单（哪些臂会动、哪几个主读数会动、哪些不动）。
- 必含：**不单调性预判** —— 本变更是否可能使任何**现已可达**的项回退？
  - 今日实证反例：补 L1 词条 → Astrocyte top3 `0.8399→0.0`（损失 1,652 细胞；`X10D/REACH_DIFF_X9A_X9B.tsv`）。
- 判据（机械）：只写「只会更好」而无回退项核查 = **Q3 FAIL**（违反 §二7）。

### Q4 判据预注册？（先冻后跑）
- 交付：主读数 / 保护门 / 失败退出条件 / 统计口径（重采样单位、重复次数、不确定性方法），**开封前冻结 sha**。
- 必含：**失败时的处置**（不移动球门：失败不撤销实现、可写负结果；禁重跑到成功/降门槛/改指标后续称同次确认）。
- 判据（机械）：判据文件无 sha 或开封后有改动痕迹 = **Q4 FAIL**。

### Q5 逃生门？（可整体回退）
- 交付：开关名 + 判值语义（哪些值=OFF）+ **回退后逐字节回旧行为**的实证方式。
- 要求：开关必须**入册** `env_switch_registry`（名/语义/默认态/回退实证/正交性），**禁无名开关**。
- 判据（机械）：拿不出「OFF 态 == 接线前字节」的实证 = **Q5 FAIL**。
- 现有在册样式：`EYEKB_STATE_GUARD`、`EYEKB_KB9_CONSUME_GUARD`、`EYEKB_X10_TWOSTAGE`、`EYEKB_X11_TYPECOUNT`、`EYEKB_X11_CONFIRMATORY`（`C1_IMPL/M7_TWOSTAGE/env_switch_registry.md`、`x11_type_inventory_20261012/X11C/config/env_switch_registry.md`）。
- ⚠ 特别条款：**默认 ON 的行为变更**（如 `EYEKB_CN_REWRITE` 2026-10-05 翻转）必须在交付层契约（`docs/VERIFY_CONTRACT.md`）里登记为**门的前置条件**，不能只当普通开关（否则门会因配置假 FAIL——先例已在案）。

## 二、改中三件（边改边出，不许事后补）

### M1 版本件
- 任何改动**出新版本号 + 新文件**，旧版**原样保留**（可追溯）；**禁就地涂改**。
- 追加式修订用 append-only 段（先例：`CONTRACT_REGISTRY_X10C.md` §6 与「superseded-by 尾注，不改写 §1 表原行」）。
- 判据：`旧件 sha 未变` 且 `新件 sha ≠ 旧件 sha`。

### M2 影响面清单
- 逐文件 / 逐维度表（先例：`C1_IMPL/M7_TWOSTAGE/CONFIG_DIFF_ON_VS_OFF.md`）。
- 必含：不单调性条目（负向也要写）、以及**下游各臂的被动读数**。

### M3 回归门
- 预注册回归判据 + 可执行命令（先例：`G3 41/41`、`G4 三件锚`、`X11 回归电池`、`M1 固定测试电池 14 样例`）。
- 必含 **OFF 恒等演练**（关断后逐字节回旧行为），且演练证据落盘（先例：`M7_TWOSTAGE/drill/ASSERT_M7_OFF_IDENTITY.json`、`ESCAPE_GATE_RECORD.json` 的 `on/off agg` 双值）。

## 三、改后四证（缺一不许收口）

### E1 sha 实证
- 新件 + 全部**回归对象**的 sha 现取（禁引用旧报告数字）。多版本冻结清单并存时，必须写明**现行指针**（见 §四 F1）。
- 判据：`sha256sum -c <FREEZE_*.sha256>` 输出逐行 OK（或被取代行有显式指针说明）。

### E2 回退恒等实证
- 关断逃生门后**逐字节回旧行为**：需**两条独立路径对拍**（先例：`x11_switch.py --mode compare` 的 `off_sha256` vs 直接 import 冻结引擎直算 sha）。
- 判据：两路 sha 相等（相等才算「可整体回退」）。

### E3 差分读数
- 前后逐条差分（含负向）；**禁只报增益**。
- 判据：差分表齐备且含 `loss/负向` 列（先例：`REACH_DIFF_X9A_X9B.tsv` 有 `gain_cells_top3` 与 `loss_cells_top3` 双列，并在报告 §3.1 如实点出回退）。

### E4 台账登记
- 在本项目**唯一归属表** `PIPELINE_REGISTRY.tsv` 中更新该件行：版本 / sha256 / 字节 / mtime / 状态 / 变更口 / 门状态；
- 登记后重跑 `scripts/build_registry.py` 并核 `REGISTRY_BUILD_REPORT.json`（rows/missing 计数）。
- 判据：台账行 sha 与盘上现取 sha 相等；登记**晚于**改动（时间序正确）。

## 四、必备配套三条（今日实证，缺则本单不完整）

### F1 多版本冻结清单必须带「现行指针」
- 实证（2026-10-12 实测）：`gold/FREEZE_GOLD_X9A.sha256`（v1，516 B）与 `FREEZE_GOLD_X9A_v11.sha256`（v11，81 B）并存；
  `sha256sum -c FREEZE_GOLD_X9A.sha256` → 5 件 OK、**`x9a_input.h5ad` FAILED**（v1 记 `f50d9316…`，盘上 v11 = `e1c19466…`）。
- 危害：FAIL 无法区分「文件损坏」与「已被新版本取代」→ 验收方会误判。
- 要求：多版本共存时，必须有一个显式指针（`CURRENT` 行/POINTER 文件/清单头部注明「现行=x11 版」）。

### F2 append-only 与「superseded」标记分开写
- 版本串被取代时：**原行保留**，另加尾注标记 superseded-by（先例：`D-X10C2S-01` → `-02`）。禁改写原行。

### F3 长卡执行中必须重读 comment/更正令
- 单轮 ≥20 分钟的变更卡：每 15-20 分钟重读一次任务评论；出现晚于开工时刻的更正令 ⇒ 停手按新规格返工；
  handoff 里显式记录「更正令到达时刻 vs 发现时刻」。

### F6 并发写作窗口 ⇒ 台账必须带「快照时刻」，活跃件归作者卡登记终态
- 实证（2026-10-12 17:36-17:39，本卡自检抓出）：`mcp_server/eyekb_core.py` 在**登记窗口内**被并发卡（W2 线路，接线
  `species_route`）改写——本表首建时 sha `f05f682d…`，3 分钟后自检重算 `ca8bab16…`；同窗口 `server.py`、新件
  `species_route.py`（W2）与 `W1_GENNORM/*`（W1）陆续落盘。
- 危害：台账 sha 会「自己过期」，收口自检会报 MISMATCH 而被误读为「台账造假」。
- 要求：
  1. 台账构建产物**必须记录快照时刻**（本卡：`REGISTRY_BUILD_REPORT.json.generated_at`）；
  2. **活跃变更件（登记窗口内有写入）在行内显式标 LIVE**，并写明「sha=构建时刻快照，终态由作者卡登记」；
  3. 收口自检对 LIVE 行的 MISMATCH **不判失败**，改为「按新快照重取 + 记一条版本注记」；
  4. 并发窗口内**不得**对他卡正在写的件做任何写操作（只读登记），也不得把缺件当失误（如本卡快照时
     `SLOT_RULE_SPEC.md` 尚未落盘）。
