# Knowledge-guided single-cell annotation reading system (EyeKB mode)

## One-line project characterization (PI correction settled 2026-09-27; unified wording for external use / README / reports)
EyeKB = **a four-layer system in which the structured ophthalmic knowledge base (KB, served over MCP) is the evidence surface, the RAG literature corpus is the evidence foundation and audit chain, and Wiki/Skill are the governance and operational memory, with multiple LLM reader seats producing single-cell annotations by voting**.
- Do not conflate the four roles: KB supplies evidence (entries / baselines / disease thin layers / developmental axis), RAG supplies provenance (the corpus pool), Wiki governs calibers (the reader seats do not read it), MCP does delivery.
- **"Using RAG to do annotation" is a claim BTEST falsified**: the free-query arm (raw retrieval) did not meet the bar — harm flowed back + cost 82×; only the finished-product KB evidence surface delivers efficacy. RAG is the ore, KB is the smelted steel; annotation uses the steel.
- The KB is the system's most valuable asset: mirror-repo acceptance MUST reconcile every kb/ file against the live copy byte-for-byte by sha (see the project-github-export test gates).

## PI doctrine (as-is decisions of 2026-09-23; read before starting any annotation task)

1. **Annotation has two independent dimensions; missing either voids the result**:
   - ① **Labels are right** — before starting you MUST know the cell-composition list and approximate proportions for that species and tissue (the composition prior), and the annotation result must be locatable within the prior; if it cannot be located → flag as unexpected and submit for review; labels MUST NOT be forced
   - ② **Separable** — the dimensionality-reduction clustering must genuinely separate; for clusters judged "unseparable" labels MUST NOT be forced — set the split-or-report flag and hand to the PI; annotating a mixed cluster is meaningless
2. **Anything added to the knowledge base must have a reason and a basis**: entries without provenance (PMID / dataset + evidence grade) MUST NOT be admitted; articles are filed into the RAG by "the reason they were put in" (inclusion_reason); finally build the links in the wiki
3. **A prior is not truth** (PI: "our PDR annotation may not be accurate either"): when a prior conflicts with the data → flag and report; you MUST NOT bend the data to fit the prior; ground truth rests in the PI's clinical reading
4. **Disease context should enter the judgment** (proliferative diabetic retinopathy → expected vascular proliferation / tip-cell state), but rules act only as **priors and QC flags** (expected / unexpected / contamination-suspect), never as final labels — guarding against prior-anchoring bias

## Knowledge reading-layer structure (three layers, every one with evidence provenance)

| Layer | Content | Entry structure |
|---|---|---|
| Composition baseline | species×tissue → cell-type list + proportion **ranges** (atlas-data driven + literature anchors; false precision forbidden) | per cell type: expected proportion range + PMID + evidence grade |
| Disease entry | disease×tissue → context / expected-cell matrix / unexpected flag / contamination flag (blood / pigment / lysis) | two-level **cell type × state** (Macrophage: homeostatic MRC1+ / foamy GPNMB+ / inflammatory CCL3+) |
| Local marker authority layer | cell-type panel + gene reverse lookup | each marker carries its source (canonical, or PMID / data-driven provenance) + version number |

- **Anti-library-bloat iron rule**: most disease features are "states", not "new cell types"; entries are organized at the type×state two levels, otherwise duplicate entries grow out of control
- **Coverage rolls forward along the disease spectrum of incoming samples** (PDR membrane → AMD/RPE-choroid → glaucoma optic nerve → ocular surface); the "do all diseases at once" trap is forbidden; new disease data entering the door gets its entry built in passing (marginal cost 0.5-1 day per entry)

## RAG filing by inclusion reason (the PI's hard requirement)

- Paper-level additive field `inclusion_reason`; enum frozen: `composition_baseline` / `disease_cell_composition` / `state_signature` / `method_reference` / `disease_mechanism_background`
- Additive metadata only — the chunks' text and vectors are untouched; existing items are semi-automatically filed + sampled for manual verification; gap-closing sets are searched by reason and admitted (the corpus is a "reading-basis library", not an unindexed pile of literature)

## Human-in-loop MCP annotation mode

```
Cluster marker extraction
  → agent calls MCP: query_marker (local-first discipline) → search_literature (literature evidence + PMID)
                  → get_disease_prior / get_tissue_composition (comparison against the priors)
  → draft labels + confidence + literature basis
  → PI confirms / overrides ← the human–machine core; disagreement between the two layers is itself a QC signal
  → final label written back to obs
```

- Every draft file header MUST carry: [Draft pending PI confirmation — human-in-loop mode, not an engine-automatic annotation]
- The whole run keeps an MCP-call jsonl trail (a reproducible chain); for every cluster give top markers + local KB hits + literature evidence + confidence + composition
- **Service-layer qualification gate**: the three tools' self-test + golden regression (for the same query, the MCP call vs the direct call must match **item by item**, PMID order and scores included; 41/41 is the measured standard)
- MCP runs on local stdio and opens no network port. Evidence-consumption discipline v2 (the PI's decision of 2026-09-26, replacing the Claude5-era "no entry into scoring" clause; see /mnt/D/OcularKB/WIKI/USER_DIRECTIVE_20260926_redline_rewrite.md): the annotation/reading side consuming RAG/MCP/literature evidence = legitimate and a core of the design; the scoring/adjudication side (truth matching, hit rates, consensus adjudication, any auto-scoring / confidence weighting / composite QC score) MUST NOT consume evidence that is same-sourced with the readings; if an auto-scoring stack (GBDT/LLM-judge) is ever added, evidence features require separate PI approval

## REVIEWER_LLM methodology ruling (review response of 2026-09-23; the basis for protocol v2 revisions — where it conflicts with the text above, this section prevails)

Overall verdict: the direction is right, but the scope of proof MUST be limited — the engineering regressions (golden set 10/10, MCP 41/41) prove only that the tool layer does not distort, **not that the disease/tissue labels are correct**; the project mainline shifts from "expanding knowledge" to "building auditable evidence of correctness".

- **Two dimensions → two goals + three gates**: the identity-evidence gate / the population-resolution gate / the **technical-credibility gate** (doublets / ambient RNA / low quality / donor effects / structural changes introduced by integration). The doublet rate is a technical metric, not a resolution metric; a globally fixed threshold MUST NOT be used (calibrate per library × major cell class × label tier: development-set selection → independent-donor validation → freeze); UMAP / silhouette / batch-mixing metrics do not get standalone pass gates
- **The correct handling of "separable"**: continuous states (monocyte→macrophage, activation, proliferation) are allowed to exist; forcing a split = manufacturing false subtypes; split-or-report expands to **three dispositions** — split only when evidenced / keep the coarser label / report the continuous unresolved population; splitting is not the default remedy; the resolution-stability assessment asks whether the "identity conclusion" is retained, not whether the cluster numbers are stable
- **Grading of composition-baseline anchors**: the primary anchor = same species + **same sampling material** + comparable data from the same disease stage (for PDR membranes the primary anchor = fibrovascular-membrane datasets; healthy retina is demoted to identity reference only; vitreous fluid will get its own baseline in future); every entry MUST record: sampling material / disease stage / treatment background / scRNA vs snRNA / enrichment steps / donor count; proportions = a conditional reference distribution, not a target; compute distributions at the **donor level** (never pool first and treat large donors as strong evidence); if the literature is only qualitative, store it qualitatively — fabricating ranges is MUST NOT; a missing proportion does not block annotation
- **Four-stage anchoring guard**: ① data-first (disease groups masked): QC + candidate identities, then freeze ② disease comparison: output only consistency/conflict flags + citations ③ relabeling MUST cite new data evidence ("fits the disease expectation better" is not a ground for relabeling) ④ PI adjudication keeps both the pre- and post-relabel labels. on/off comparisons require an independent reading group or order balancing (the same person seeing "on" first and then "blinded review" of "off" is invalid — PRIOR_DIFF-type designs must be hardened accordingly)
- **Four unexpected classes**: beyond the baseline's coverage / conflicts with existing material / technically suspect / candidate biological phenomenon — queue them separately, never in one pot
- **Type×state implementation**: hierarchical identity + multiple coexisting state axes; stable concept-ID ↔ canonical-name ↔ synonym mapping to prevent bloat (similar names are not auto-merged, differing names are not auto-split); evidence is recorded down to the figure-panel location + counterexamples + applicability conditions; transcriptional similarity ≠ developmental origin
- **Three RAG fields**: inclusion_reason (five classes, multi-select) + claim_relation (support / refute / qualify + the specific claim's location) + evidence_context (species / material / conditions / figure anchor); different paragraphs of one paper can support different claims; a 50-paper random spot-check ≠ formal acceptance — the key claims of D0 rules require **line-by-line verification**, and unverified items are marked with their status
- **T6 project priorities**: ① a stratified-annotation evaluation set + a frozen evaluation protocol (donor-level development/test splits, reporting error rate / coverage / abstention rate) ② external validation on independent PDR material + orthogonal validation of key disputed points ③ validation of the D0 reading-loop's payoff (metrics = corrections confirmed by independent re-review / errors introduced / unresolved-but-reasonably-kept / re-review time cost, **not "how many labels were changed"**). Deferred: human–mouse alignment, widening the disease layer, the v2_prod switch (limited to independent evaluation within the adult-retina domain); the M1 positioning = "ophthalmic annotation infrastructure with an explicit application domain" — knowledge-base size is not the center of the methodological contribution
- **T7 correctness standard without ground truth**: per-cluster evidence cards (candidate identity + alternative candidates / cross-sample contribution / supporting and refuting evidence / technical explanation / robustness before vs after integration / the tier to which the ruling is accepted + unresolved items); independence is measured per donor (thousands of cells from the same donor ≠ thousands of independent validations); the **out-of-domain-use audit is the first audit item** (the engine / marker library's domain of applicability vs the sample material's match)
- **Manifest-caliber completeness**: the species classification counts MUST sum to the total row count (a 13,514-row gap across other+unknown+method was measured and challenged by the REVIEWER_LLM); the behavior of unlabeled classes in filtered retrieval must be spelled out to prevent hidden omissions

## Red line: the developmental axis is a separate category (PI decision 2026-09-23; same tier as the two-dimension doctrine)

- **Fetal/developing-stage and adult samples must not be merged into one entry even for the same tissue**: development_stage is a first-class axis on par with species and tissue; baselines, disease matrices, evaluation sets, RAG labels, and MCP outputs all carry it. **Frozen ruling (KB2c, 2026-09-23; the project maintainer decided per the runner script's recommended values to the six questions)**: the top-level axis `organism_stage` has four levels {fetal, adult, developing, unknown} + a per-row UBERON raw-value column for provenance (postnatal→developing, organoid→unknown+flag); adult is determined by donor_age ≥18y (newborn/child/adolescent→developing; no age source→unknown + a disclosure row; silent assignment to adult MUST NOT happen); **the primary delivery tier = adult-only** (drop every non-adult donor unit and recompute the donor-level distributions — measured 48/307 dropped); the existing mixed caliber is demoted to the adult_pool comparison tier, and the two tiers' entry_id/identity signatures are kept separate; for fetal, only transitional-state conceptual entries are built for now, with no computed composition (candidates GSE268630/GSE137828/GSE137863/the organoid artifact, marked "requires a fetal reference pipeline; the current engine does not apply"); **aging (the ≥60 elderly stratum) is an independent axis orthogonal to development**, to get its own entries in the future, never folded into organism_stage; ruling file /mnt/D/EyeKB/plans/KB2C_ADJUDICATION_20260923.md
- The fetal_retina baseline is entered independently of adult_retina; the keys of the disease×material matrix cells carry the developmental axis; in the evaluation layer the fetal set is always OOD-strict (an adult engine seeing fetal data MUST abstain — the red line expressed in the exam); fetal reference candidates form a separate category (GSE268630 human-fetal multiome / GSE137828 / GSE137863 / the organoid artifact, marked "requires a fetal reference pipeline; the current engine does not apply")
- External phrasing: any "cell composition of tissue XX" claim must be able to answer "which developmental stage" — a claim that cannot answer is incomplete

## Pitfalls (GSE165784 PDR-membrane demo, evidenced 2026-09-23)

- **Local-KB blind spot**: a healthy-atlas marker library applied to disease samples → vascular/stromal/immune all 0 hits (the PDR membrane is 80% myeloid; the healthy-retina library's 10 classes have 0 coverage) → the library MUST include disease-state / membrane / immune panels
- **Batch bleeding across cluster boundaries**: a cluster made almost entirely of one sample = a sample-effect signal; use integration (harmony etc.) + a **dual-track marker consistency check before vs after integration** (to prevent integration from erasing real signal)
- **n=1 controls**: between-group comparisons stay descriptive; statistical claims MUST NOT be made
- **Unexpected clusters are opportunities, not errors**: for an unexpected signature, suspect a doublet / contamination first — yet once verified it may be a valuable finding, so keep the flag
- **Diff-table discipline**: every re-clustering / optimization MUST produce a v1→v2 diff table (each cluster's destination + purity + whether semantics changed + basis); all old-version artifacts are retained
- **Guard against disease-centric narrowing (the PI's correction: "why focus on PDR — we are building a general ophthalmology system")**: the reading-layer architecture = a tissue-anchored general layer (composition baselines anchored on the registry's **already-annotated standard sets** D001/D002; skeletons for other tissues await inventory backfill — no force-fitting) + a thin disease-layer matrix (each disease merely fills one cell of the matrix); evaluation ground truth uses only already-annotated datasets. For any new scenario, first ask "how does the general layer cover it", then "how to fill the disease entry"; the whole architecture MUST NOT be designed around a single disease/sample
- The two dimensions of the annotation protocol are written down (ANNOTATION_PROTOCOL_v1.md) and maintained together with the knowledge layer; new sessions / new runner scripts MUST read it before annotating

## Fix-type evaluation = two-track design (RUN7RG→FACEV21, evidenced 2026-09-25/26; criteria-level lesson)

- **A single-target acceptance test inevitably carries hidden damage**: the v6 fix beat the line by +2 on the 22 hotspot targets, yet of the 23 same-exam control clusters ("both seats originally right") 4 flipped wrong (a quality flag mistaken as grounds for downgrade-abstention / cross-species ranking noise / a new entry introducing a lineage conflict) — overall FAIL. Fix/upgrade evaluations **MUST pair a "no-harm line"** (the control group's flipped-to-wrong count gets its own independent gate); a single-metric PASS is not grounds for activation.
- **Retest trio**: same targets + same goalposts (not lowered by one word) + a **preservation clause** (the gain clusters named this round may not be lost). Attribution predictions can be tested in a chain: FACEV21's newly fixed clusters were exactly the residue RUN4-r's attribution predicted — the decompose-first-then-retest sequencing is the root of attribution credibility.
- **Once the harm is localized to the "surface" layer, defuse it at the pinpoint and retest** — more accurate than rolling back assets: after the RUN7RG FAIL, v6 was not reverted; instead the three poison points got pinpoint repairs (add the "not usable as downgrade grounds" instruction to the flag row / drop the ranking on the cross-species clusters / set a decision order for the conflicts) + a new prereg sha first; the retest passed both gates with R1 19/22, R2 0/23 — the net gain was preserved and the harm is cleaner than the old baseline.
- **Behavioral metrics for knowledge injection = keep citation rate and compliance rate separate**: the soft prompts' first real-traffic test — the note was cited in 23/24 ballots' reasons, yet all three seats still judged the target case wrong. "Seen, cited, not followed": prompts change wording, not decisions. Disposition in the user's decision style = first bank it as paper material as a negative result, no silent escalation to hard prompts, no threshold shrinking.
- **Above the entry layer there is a ceiling for misleading sources**: after deleting the misleading entries and the hint, the readings actually got worse — gene-set co-expression prior ambiguity (e.g., MG↔Astro's GLUL/VIM/CLU); dictionary fixes cannot solve this class of cases — record it in limitations, and do not promise "dictionary fixes cure all".
- Residual errors that are consistently attributed round by round (degenerate clusters / genuine panel gaps) are booked as the known ceiling; **adding tests to pad scores is MUST NOT** (goalpost-move guard); "the fix improves X%" may be reported only over preregistered question sets, never generalized; until the numbers are out, all external communication maintains the pre-fix caliber. Connects with the "KB quality three layers" (gap scan + stock QC + prior anti-contamination): the efficacy retest is the completion ring of the fourth layer.

## The RUN4 era (2026-09-24 late-night evidence: FAIL → responsibility decomposition → third-voter voting; entry naming ontologized)

- **RUN4's main race settled as FAIL** (R1 13/22 < the goalpost 15; R2 2 flips > the tolerance of 1): responsibility decomposition showed that of the 9 unfixed clusters only 3 were true panel gaps; 3 were non-decisive readings (one side named, the other abstained — the strict double-reading protocol voided the whole question); 2 were expectedly unfixable; 1 was out of range; both R2 flips were B-side abstention shifts while the A side had zero flips = reading jitter, not panel harm → **v5 panels are kept, no rollback; the loop is not declared closed**.
